# Silkyway Messaging Flow

This document describes the comprehensive messaging flow in the Silkyway marketplace and the key files involved.

## Core Components

### 1. Client-Side Components

**ConversationFeed.tsx**
- Location: `/src/components/inbox/ConversationFeed.tsx`
- Purpose: Displays messages in a conversation and handles sending new messages
- Key functionality:
  - Connects to Socket.IO and joins conversation rooms
  - Subscribes to real-time message events
  - Handles message sending and optimistic updates
  - Manages message attachments and emoji selection
  - Handles read status updates

**ConversationTab.tsx**
- Location: `/src/components/inbox/ConversationTab.tsx`
- Purpose: Displays conversation information in the sidebar
- Key functionality:
  - Shows listing details (image, title, price)
  - Displays unread message indicators
  - Handles conversation selection

**useSocket.ts**
- Location: `/src/hooks/useSocket.ts`
- Purpose: Custom hook for Socket.IO client functionality
- Key functionality:
  - Initializes Socket.IO connection
  - Provides methods for joining/leaving conversations
  - Handles message sending
  - Manages subscription to Socket.IO events
  - Handles connection status

### 2. Server-Side Components

**socketio.ts**
- Location: `/src/lib/socketio.ts`
- Purpose: Initializes Socket.IO server in the Next.js Pages Router
- Key functionality:
  - Sets up Socket.IO server
  - Configures CORS and connection settings
  - Handles user authentication
  - Sets up event handlers for socket connections

**socketio-server.ts**
- Location: `/src/lib/socketio-server.ts`
- Purpose: Provides global access to Socket.IO server instance
- Key functionality:
  - Stores and retrieves Socket.IO server instance
  - Provides helper functions for emitting events
  - Implements retry logic for message delivery

**socket.ts**
- Location: `/src/pages/api/socket.ts`
- Purpose: API route for Socket.IO server in Pages Router
- Key functionality:
  - Initializes Socket.IO server
  - Handles WebSocket connections
  - Configures API route for Socket.IO

## Messaging Flow

1. **Initialization**:
   - When the app loads, the Socket.IO client is initialized in `useSocket.ts`
   - The client connects to the server via `/api/socket` endpoint
   - The Socket.IO server is initialized in `socketio.ts` and stored globally in `socketio-server.ts`

2. **Joining Conversations**:
   - When a user opens a conversation in `ConversationFeed.tsx`, it calls `joinConversation(conversationId)`
   - This emits a `join-conversation` event to the server
   - The server adds the socket to the conversation room: `conversation:${conversationId}`

3. **Sending Messages**:
   - User types a message and clicks send in `ConversationFeed.tsx`
   - The component calls `sendMessage(conversationId, messageData)`
   - This emits a `send-message` event to the server with the message data
   - The server receives the event in `socketio.ts` and processes it in `setupSocketEventHandlers`
   - The server then:
     - Broadcasts to the conversation room: `socket.to(conversation:${conversationId}).emit('new-message', data)`
     - Broadcasts directly to the recipient's user room: `socket.to(user:${receiverId}).emit('new-message', data)`
     - Broadcasts to all sockets in the conversation room: `io.to(conversation:${conversationId}).emit('new-message', data)`

4. **Receiving Messages**:
   - The recipient's `ConversationFeed.tsx` is subscribed to the `new-message` event
   - When a message is received, it updates the messages state with `setMessages()`
   - It also updates the conversation object to include the new message
   - The component then scrolls to the bottom of the feed to show the new message

5. **Read Status Updates**:
   - When a user views a conversation, `markMessagesAsRead(conversationId)` is called
   - This makes an API call to `/api/conversations/${conversationId}/view`
   - After successful marking, it emits a `message-read` event to notify other participants
   - Recipients update their message UI to show read status

## Data Flow for Listing Information

The listing information displayed in `ConversationTab.tsx` follows this flow:

1. Conversation data is fetched from the database, including listing details
2. The `ConversationTab` component extracts listing information:
   - Title: `listing?.title || 'Untitled Listing'`
   - Image: Complex extraction logic with multiple fallbacks
   - Price: `listing?.price || 0`
   - Currency: `normalizeCurrency(listing?.currency || 'USD')`
3. The component uses the `usePrice` hook to format the price according to user preferences
4. The listing information is displayed in the conversation tab

## Recent Fixes

1. **Real-time message delivery**:
   - Enhanced the Socket.IO implementation to properly broadcast messages to both the conversation room and directly to the recipient's user room
   - Added redundant broadcasting to ensure messages are delivered even if room membership is inconsistent
   - Fixed the Socket.IO server configuration to properly pass the io instance to event handlers

2. **Improved ConversationFeed component**:
   - Updated to handle both direct conversation messages and global broadcasts
   - Enhanced duplicate detection to prevent message duplication
   - Added conversation state updates when new messages arrive
   - Improved timestamp-based message deduplication

3. **Enhanced ConversationTab component**:
   - Added better debugging to track listing data issues
   - Improved logging of the raw listing object to identify data structure issues
   - Added conversation ID tracking for better debugging

These changes ensure that messages appear immediately for all participants without requiring a page reload, and that listing information is properly displayed for all users in a conversation.
